# ごほうびの仕組みと、ゲームに共通する決まり

作成日: 2026-09-26

## 全体の形: 土台の上に、勉強とゲームが乗る

```
┌──────── べんきょう（STUDIES） ────────┐   ┌───────────── ゲーム（GAMES） ─────────────┐
│ こくご / さんすう / …                 │   │ サバイバー / ひっぱりアタック / …           │
│ 問題を作るだけ（StudyDef.build）      │   │ タイトル画面から先はぜんぶゲームが作る      │
│                                       │   │ （つよくする・ステージえらび・遊ぶ・結果）  │
│                                       │   │ 画像もゲームごと（art/games/<id>）          │
└───────────────────┬───────────────────┘   └──────────────────┬────────────────────────┘
                    ▼                                          ▼ Platform（券・コイン・強化・保存）
┌──────────────────────────────── 土台（プラットフォーム） ─────────────────────────────────┐
│ 子ども・学年・アバター / 問題の記録と定着度（applyAnswer）/ コイン・ゲーム券              │
│ ホーム・クエスト画面・ゲームをえらぶ画面（ここまで）                                     │
└──────────────────────────────────────────────────────────────────────────────────────────┘
```

- 勉強もゲームも、登録簿に1つ足せば画面・保存データ・ごほうびに自動でつながる。
  - 勉強: `src/studies/registry.ts` の `STUDIES`（形は `src/studies/types.ts`）
  - ゲーム: `src/games/registry.ts` の `GAMES`（形は `src/games/types.ts`）
- 勉強とゲームは直接つながらない。つながりはコインとゲーム券だけ（土台が持つ）。
- **土台がやるのは「ゲームをえらぶ」まで。** えらぶと、そのゲームのタイトル画面に入り、独立したゲームとして見せる。
- ゲームは、ゲーム券・コイン・強化・保存を、土台からもらう `Platform`（`src/games/types.ts`）を通してだけさわる。こうして共通の決まり（券1枚で1回、コインは `finishGame` で計算、強化は25コイン）をゲームごとにばらばらにしない。
- ゲームごとの設計は `docs/games/<id>.md`（ひな形は `docs/games/_template.md`）。

## 全体の流れ

```
べんきょう（クエスト） ──→ 🪙コイン（毎回）
      │                     🎟️ゲーム券（その日はじめての教科ごとに）
      ▼
ゲームをえらぶ ──🎟️1まい──→ あそぶ ──→ 🪙コイン（少し）＋ ゲームの進みぐあい
      │
      └─ つよくする（ゲームごと） ←── 🪙コイン
```

- 通貨はコインひとつだけにする（以前の 🪶ことばの羽・⭐ひかりの星 は廃止。古いデータは1個=1コインで換算）。
- 教科をまんべんなくやらせる役目は、ゲーム券に持たせる。コインは教科によって変えない。
- 「教科」は `STUDIES` に登録した勉強1つのこと。勉強を足すと、その勉強でもその日はじめてなら券がもらえる（1日の上限は変わらない）。

## ゲーム券

| ルール | 初期値 | 設定 |
|---|---|---|
| 毎日、無料でもらえる券 | 0枚 | `freePlaysPerDay` |
| その日はじめてやった教科ごとにもらえる券 | 1枚 | `playsPerSubject` |
| 勉強でもらえる券の1日の上限 | 3枚 | `ticketsPerDay` |

- どれも「おうちのひと」画面で変えられる。
- 同じ教科を2回目以降やっても券は増えない（コインはもらえる）。券をもっと欲しければ、別の教科をやる。
- 使わなかった券は次の日に持ち越す（今までどおり）。
- ゲーム券は全ゲーム共通。どのゲームで使ってもよい。

## 勉強のえらび方と、問題の出し方

```
ホーム ─[こくご]→ 学年のタブ（はじめは自分の学年 ★） → ⭐まぜこぜ（おすすめ） / カテゴリ（かんじを かく・おくりがな …）
```

- 教科の中を **学年ごとのカテゴリ**（`Category`、`src/studies/types.ts`）に分ける。子どもは「まぜこぜ」か、好きなカテゴリをえらぶ。
- 下の学年・上の学年のタブもえらべる。ただし下の学年はコインがかなり少なく、ゲーム券もない（下の表）。
- えらぶ画面に、全問正解したときのコイン（「さいだい 30」）と、ふくしゅう・あたらしい問題の数を出す。
- 1回は **5問**（おうちのひと画面の `questLength` で3〜10に変えられる）。

### 問題の選び方（Anki と同じ考え方、`planSet()`）

各カテゴリは **問題プール**（カードの一覧。まだやっていない問題はこの順＝やさしい順に出す）を持つ。1回ぶんは次の順でえらぶ。

1. **復習の日が来た問題**。定着していないもの（連続正解が少ないもの）→ 期限が古いもの の順。
2. **まだやっていない問題**。復習がたまっていても **2問は入れる**（`NEW_PER_SET`）。まぜこぜでは、カテゴリから順番に1つずつとる。
3. 足りなければ、**復習の日がまだ来ていない問題**。
- 自分の学年の「まぜこぜ」には、**下の学年のカテゴリの、始めていて復習の日が来た問題** もまぜる（コインは減らさない）。学年が上がっても、覚えきっていない字の復習が続くようにするため。
- まぜこぜでは、1つのカテゴリから出すのは半分まで、手書きは4割まで（5問なら3問・2問）。同じカテゴリが続かないようにならべる。
- まちがえた問題（おてほんを見た手書きも）は、**その回の最後にもう一度** 出す（1回だけ、コインなし）。

## 勉強のコイン: 定着していない問題ほど多い

1回ぶんのコイン = (**完走ボーナス 10** + **正解した問題ごとのコイン**) × **倍率**（切り上げ）

| 問題の状態（答える前） | コイン | ねらい |
|---|---|---|
| はじめての問題 | 4 | 新しいことに挑戦する |
| 復習の日が来た問題（まだ定着していない: 連続正解 0〜1回） | 4 | 苦手を直す |
| 復習の日が来た問題（連続正解 2〜3回） | 3 | |
| 復習の日が来た問題（よく定着している: 連続正解 4回以上） | 2 | |
| 復習の日がまだ来ていない問題（同じ日のくり返しなど） | 1 | くり返しだけで稼げないようにする |
| おてほんを見て正解 | 1 | |
| まちがい・最後のやりなおし | 0 | （完走ボーナスがあるので0にはならない） |

| えらんだもの | 倍率 | ゲーム券 | ねらい |
|---|---|---|---|
| 自分の学年（上の学年も）・まぜこぜ | ×1.0 | あり | いろいろな種類をまぜて解くほうが覚えやすい |
| 自分の学年（上の学年も）・カテゴリ | ×0.7 | あり | 好きなものをえらべるが、まぜこぜのほうが得 |
| 下の学年（まぜこぜでもカテゴリでも） | ×0.3 | **なし** | かんたんな問題でコインや券を集められないようにする |

- 「定着度」は、Anki と同じ考え方の間隔反復カード（`src/learn/srs.ts`、正解するたびに1→2→4→7→14→30日後に出す）で測る。
- すべての問題が「1問＝1枚のカード」（例: `kanji:字`、`keisan:7+8`、`tokei:3:30`、`okuri:新しい`）。出す順番とコインの両方に使う。
- 同じ教科を何回やってもコインは減らない。ただし同じ問題をくり返すと1コインになるので、結果として新しい問題・苦手な問題をやる方が得になる。
- 目安: 自分の学年のまぜこぜで新しい問題を5問全部正解すると 30、カテゴリなら 21、下の学年なら 9。

## ゲームに共通する決まり

新しいゲームを足すときは、次を満たすようにする。コードでの形は `src/games/types.ts` にある。

### 1. 登録

- `src/games/registry.ts` の `GAMES` に `GameDef` を1つ追加すれば、ゲームをえらぶ画面と保存データに自動で出てくる。
- ゲームのファイルは `src/games/<id>/` にまとめる（`index.ts` に `GameDef`、`main.ts` にタイトル画面から先、`style.css` に見た目、`assets.gen.ts` に画像の対応表）。画像は `art/games/<id>/`（[02-asset-generation.md](02-asset-generation.md)）。
- `GameDef` に書くもの: `id`（保存データのキーになるので後から変えない）、名前、ひとこと説明、ゲームをえらぶ画面の絵 `cover`（ゲームの画像から）、ステージの数 `stages`、強化の一覧、ゲームを読みこむ関数 `load()`。
- `load()` は `GameModule` を返す。`open(root, platform)` で `root` の中にタイトル画面を出し、そこから先はゲームが作る。もどるときは `platform.exit()`。
- Phaser などの重いものは `load()` の中で `import()` して、遊ぶときだけ読む。
- ゲームの画面で使える部品が `src/games/kit/` にある（コインと券の表示・つよくするパネル・やめるボタン・結果パネル・Phaser でシートを読む関数）。使うかどうか、どう見せるかはゲームが決める。

`Platform` でやること（ゲームの中で自分でやらない）:

| やること | 使うもの |
|---|---|
| 1回遊ぶ（ゲーム券を1まい使う） | `startRun(stage)` → 強化レベル・やさしい設定がもらえる。券がない・まだ遊べないステージなら `null` |
| 結果をわたす（コインと進みぐあいの計算） | `endRun({ cleared, stage, score })` → もらえたコイン |
| 強化を買う | `upgradeLevel` / `upgradeCost` / `canUpgrade` / `buyUpgrade` |
| 遊べるステージ | `maxStage()`（クリアした一番先 + 1） |
| ゲームだけの保存（えらんだキャラなど、強さに関係しないもの） | `data()` / `saveData()` |
| ゲームの中のクイズ（8.） | `quiz(title, note)` |

### 2. 1回の長さ

- 1回は **2〜4分** くらいで終わる（勉強1回と同じくらい）。
- 途中でやめられる（「やめる」ボタン。`kit/ui.ts` の `quitButton`）。やめたときも `endRun`（負け）を呼び、結果の画面に行く。参加コインはもらえる。

### 3. ステージ（進みぐあい）

- ゲームは **ステージ番号（1, 2, 3, …）** を持ち、後のステージほど難しくする。
- 保存データにはゲームごとに「クリアした一番先のステージ」「ベスト記録」「遊んだ回数」「クリアした回数」「強化のレベル」を持つ（`GameProgress`）。
- 次に遊ぶのは「クリアした一番先のステージ + 1」（`stages` をこえない。全部クリアしたら最後のステージをくり返す）。クリアしたステージを遊び直せるようにしてもよい。
- ステージのないゲームは `stages: 1` にする（いつもステージ1）。

### 4. 2つの成長を分ける: 「ずっと残る強化」と「1回だけの成長」

どのゲームも、成長を次の2つにはっきり分ける。

| | ずっと残る強化（永続） | 1回だけの成長（ラン内） |
|---|---|---|
| 例（サバイバー） | たいりょく・こうげき・すばやさ・じしゃく（`GameDef.upgrades`） | レベルアップで選ぶスキル（`src/games/survivor/skills.ts`） |
| 例（ひっぱりアタック） | たいりょく・こうげき・いきおい・かいふく | 敵の波をたおすたびに選ぶスキル（`src/games/hippari/skills.ts`） |
| 手に入れ方 | 🪙コイン（勉強とゲームのクリア） | そのプレイ中の経験値・アイテム |
| 残るか | 保存され、次のプレイにも残る | そのプレイが終わると消える |
| 中身 | **基本の数値だけ**（体力・攻撃力・速さなど）。1段階の効果は小さく一定 | **遊び方が変わるもの**（新しいわざ・武器・組み合わせ）。毎回ちがう選び方ができる |
| 役目 | 勉強の成果が「先のステージに進める力」になる | 1回1回のプレイを楽しくし、飽きさせない |

守ること:

- 永続強化で新しいわざや遊び方を解放しない。遊び方の変化はラン内の成長に任せる（コインで買えるのは数値だけにして、ゲームの楽しさがコインの量で決まらないようにする）。
- ラン内の成長は、永続強化のレベルによらず毎回ゼロから始まる。永続強化はその「土台」を少し上げるだけ。
- ゲーム中にクイズを入れる場合（基本は入れない。8.）、その効果はラン内の成長だけにかける。永続強化やコインには影響させない。
- 難しさ（5.）の推奨強化レベルは、「ふつうにラン内で成長したうえで」永続強化がそのレベルならクリアできる、という意味で決める。

### 5. 難しさの上げ方: 「ゲームクリア + 勉強1回ぶん」で次のステージへ

ねらい: はじめの数ステージはゲームだけで進めるが、そのあとは **1ステージあたり、いつも同じくらいの勉強**（クエスト1回ぶん）が要るようにする。掛け算で難しくすると、先に行くほど必要な勉強が増え続けて、どこかで進めなくなるので使わない。

- ステージごとに **推奨強化レベル**（全強化のレベルの合計）を決める: `R(n) = max(0, 2 × (n − 3))`
  - ステージ1〜3は強化なしでクリアできる。そのあとは1ステージにつき2段階ずつ増える。
- 敵の強さは、推奨強化レベルにそろえて **足し算で** 上げる（ステージが1つ進むと、強化2段階ぶん強くなる）。
- 強化1段階の効果は **足し算で一定**（例: こうげき +25%、たいりょく +1）。
- 強化の費用は **レベルによらず一定**（7.）。
- こうすると、1ステージに必要なコインは「2段階 × 25 = 50」でいつも同じになる。ゲームのクリアで28もらえるので、残りの約22（クエスト1回ぶん）を勉強で集める。
- ゲームがうまい子は推奨レベルより少ない強化で進めてよい（うでまえで先に行ける余地を残す）。

### 6. ゲームのコイン（全ゲーム共通の計算、`finishGame`）

| 結果 | コイン |
|---|---|
| 参加（負け・途中でやめたときも） | 3 |
| はじめてクリアしたステージ | 25（ステージによらず一定） |
| クリア済みのステージを再クリア | 8 |

- ゲームの中でコインを拾わせてもよいが、それは演出だけにして、もらえるコインはこの表にそろえる（ゲームごとに稼ぎやすさが変わらないように）。

### 7. ずっと残る強化（ゲームごと）

- 強化はゲームごとに分ける。1つのゲームで4つくらいまで。
- 費用は **1段階 25コインで一定**（`cost: { base: 25, step: 0 }`）。
- 全強化の最大レベルの合計を、最後のステージの推奨強化レベル以上にする（例: 4種類 × 10段階 = 40 → ステージ23まで）。ステージを増やすときは最大レベルも上げる。

### 8. 勉強とゲームは分ける: ゲーム中に無理に問題を出さない

- **基本は、勉強はクエスト、ゲームはゲームで分ける。** 勉強とのつながりはコインとゲーム券だけで十分なので、ゲームの流れを止めて問題を出すことはしない。
- 例外: クイズそのものが遊びの一部になっているゲーム（クイズで戦う、答えを選んで進むなど）なら入れてよい。「勉強させるために、ゲームの途中に問題をはさむ」のはやめる。
- 入れるときは `platform.quiz(タイトル, 説明)` を使う（中で `battleQuiz` で問題を出し、`applyAnswer` で記録する）。コインは出さず、効果はラン内の成長だけにかける（4.）。
- サバイバーのレベルアップ時のクイズは、この決まりより前に作ったもの。残すか外すかは、サバイバーの改善のときに決める。

### 9. 見た目と操作

- タブレットの横向き・縦向きの両方で遊べる。タッチだけで操作できる。
- 字が読めない年長さんでも遊べるように、説明は絵とアイコンを中心にする。
- 「やさしい」設定（年長さん）を持てるようにする（`GameContext` の `easy`）。

### つりあいの確かめ方

1日の収入の目安（2教科を1回ずつ → 券2枚、ゲーム2回）:

- 勉強: (10 + 3×5) × 2 ≈ 50
- ゲーム: 1回はじめてのクリア・1回負け ≈ 31

| ステージ | 推奨強化レベル | ここまでに要るコイン | ゲームだけで貯まるコイン |
|---|---|---|---|
| 1〜3 | 0 | 0 | 84 |
| 4 | 2 | 50 | 112 |
| 6 | 6 | 150 | 168 |
| 7 | 8 | 200 | 196 ← ここから勉強のコインが要る |
| 10 | 14 | 350 | 280 |
| 20 | 34 | 850 | 560 |

1ステージ進むごとに、足りない分は約22コイン（クエスト1回ぶん）ずつ増える。券も勉強でしかもらえないので、だいたい「1日1ステージ」のペースになる。ゲームを作ったら、ステージ n を推奨強化レベル R(n) で子どもがクリアできるか、実際に遊んで確かめる。

## 新しいゲームを作るときの手順

1. このドキュメントの「ゲームに共通する決まり」を読む（特に 4. 2つの成長、5. 難しさ）。
2. ゲームの中身を決める: 1回の遊び方、ステージの進み方、**ラン内の成長**（毎回ちがう選び方ができるもの）、**永続強化**（数値だけ、4種類くらい）。
3. `docs/games/_template.md` を `docs/games/<id>.md` に写して、設計を書く（世界観・遊び方・ステージ・2つの成長・画面・画像）。
4. 画像を作る（[02-asset-generation.md](02-asset-generation.md)）: `art/games/<id>/prompts/` にプロンプト → `scripts/art/gen.sh games/<id> ...` → `art/games/<id>/art.json` → `node scripts/art/build.mjs games/<id>`。
5. `src/games/<id>/index.ts` に `GameDef` を書き、`src/games/registry.ts` の `GAMES` に足す。
6. `src/games/<id>/main.ts` に `open(root, platform)` を書く。タイトル画面（あそぶ・つよくする・もどる。ステージがあればステージえらび）→ `platform.startRun()` → 遊ぶ → `platform.endRun()` → 結果 → タイトル画面、の流れにする（コインと進みぐあいは土台が計算する。ゲームで独自にコインを配らない）。
   - 敵の強さなど、画面によらない部分は別のファイルに分けてテストを書く（例: `src/games/hippari/stages.ts`）。
   - `npm test` の `src/games/registry.test.ts` が、強化の費用・数・最大レベルの合計を全ゲームで確かめる。
7. ステージ n の敵の強さを、推奨強化レベル `recommendedLevel(n)`（`src/state/economy.ts`）でクリアできるように合わせ、実際に遊んで確かめる。
8. 下の「いまのゲーム」の表に足す。

## 新しい勉強を足すときの手順

1. カテゴリ（`Category`、`src/studies/types.ts`）を作る。問題の作り方は `src/learn/`、問題のデータは `src/data/` に置く。
   - `cards()`: 問題プール（カードのキーの一覧）。まだやっていない問題はこの順に出すので、やさしい順にならべる。数が多すぎる種類（3けたの計算など）は、決まった並びで150問くらいをえらぶ。
   - `make(card)`: カードから1問を作る。選択肢のならびなどは毎回変えてよいが、カードが同じなら同じ問題にする。
   - `grade`（学年）、`write`（手書き）、`quiz`（すぐ答えられる3択にでき、ゲームの中のクイズに使える）。
2. `src/studies/<id>.ts` に `StudyDef`（id・名前・アイコン・色・カテゴリの一覧）を書き、`src/studies/registry.ts` の `STUDIES` に足す。
3. ホームのボタン、えらぶ画面、ゲーム券（その日はじめての勉強ごと）、コインは自動でつながる。勉強の中でコインや券を配らない。
4. 文章の問題（読み取り・ことばなど）は、LLMで下書きしてよいが、答えが1つに決まるかを人が確かめてから入れる。文の中の漢字がその学年までに習う字だけかは、テスト（`src/learn/engine.test.ts`）が確かめる。

## 決めたことと理由

| 決めたこと | 理由 |
|---|---|
| 通貨はコインだけ。教科ごとの素材はやめた | 報酬が複雑になると子どもがわからない。教科のバランスはゲーム券でとる |
| ゲーム券は「その日はじめての教科ごと」。むりょう券は初期値0 | 「まず勉強、それからゲーム」にし、いろいろな教科をやる理由を作る |
| 同じ教科をくり返してもコインは減らさない。減らすのは同じ問題のくり返し | 勉強そのものは止めたくない。止めたいのは「かんたんな問題だけで稼ぐ」こと |
| 問題のコインは定着度（間隔反復）で決める | 新しい問題・苦手な問題に向かわせる |
| 問題はプールから Anki と同じ順（復習の日が来たもの → 新しいもの）でえらぶ。新しい問題は毎回2問は入れる | 忘れかけたものを先に直す。復習だけの回が続くと飽きる |
| 教科の中をカテゴリに分け、まぜこぜのコインを多くする（カテゴリは0.7倍） | 好きなものをえらべるようにしつつ、まぜて解くほうへさそう（交互練習のほうが覚えやすい） |
| 下の学年はえらべるが0.3倍・券なし。上の学年は自分の学年と同じ | かんたんな問題で稼げないようにする。先に進むのは止めない |
| 下の学年の「始めていて復習の日が来た問題」は、自分の学年のまぜこぜに入れて、コインを減らさない | 学年が上がっても、覚えきっていない字の復習は大事 |
| 1回は5問 | 10問は長い（特に指の手書き） |
| まちがえた問題は、その回の最後にもう一度（コインなし） | その場でやりなおすほうが覚えやすい |
| ゲームを選べるようにする | 子どもが飽きやすいので、気分でゲームを変えられるようにする |
| ゲーム中に無理に問題を出さない。勉強とゲームは分ける | 勉強とのつながりはコインと券で十分。ゲームの流れを止めると楽しさが減る |
| 永続強化はゲームごとに分け、数値だけにする | 遊び方の楽しさはラン内の成長で出す。コインは「先に進む力」だけにする |
| 難しさは足し算で上げ、強化の費用とクリアのコインを一定にする | 掛け算だと先に行くほど必要な勉強が増え続ける。「ゲームクリア + 勉強1回ぶん」で1ステージ進む形にする |
| はじめの数ステージはゲームのコインだけで進める | 最初は遊びの楽しさで引きこむ |
| 勉強とゲームを、同じ土台の上に並ぶ「登録簿の1つ」にする | 勉強もゲームも増やしていくので、足すたびに画面やごほうびを作り直さなくてすむようにする |
| 土台は「ゲームをえらぶ」まで。タイトル・つよくする・ステージえらび・結果はゲームが作る | ゲームごとに独立したゲームとして見せたい。見た目や遊び方の自由をゲームに持たせる |
| ただし券・コイン・強化・保存は `Platform` を通す | ゲームを独立させても、ごほうびの決まりはばらばらにしない |
| 画像はゲームごとに分ける。ゲームの主人公はアバターとちがってよい | ゲームの世界に合う見た目にしたい。ほかのゲームを変えても影響しない |
