# ゲーム候補（あそびラボ）の引き継ぎ

作成日: 2026-09-26

いまの「バトル」（ダダサバ風）は、まほうだまが強すぎてほかのスキルを選ぶ意味がほとんどなく、爽快感も足りない。そこで、バトルとは別のゲームをホームの「あそびラボ」に試作して、操作感を試した。この文書は、候補ごとに別のセッションで本格実装を進めるための引き継ぎ。

## 採用した候補（3つ）

| id | 名前 | 元にしたゲーム | ファイル | 状態 |
|---|---|---|---|---|
| `defense` | モンスターまもり | モンスターサバイバル（FARLIGHT、2026-07） | `src/lab/DefenseScene.ts` | 雛形。自動プレイでバランスを1回調整した |
| `sling` | ひっぱりアタック | モンスト（ひっぱりアクション） | `src/lab/SlingScene.ts` | 雛形。動作確認だけ（バランスは未調整） |
| `grow` | ぱくぱくビッグ | Hole.io（のみこんで大きくなる .io ゲーム） | `src/lab/GrowScene.ts` | 雛形。動作確認だけ（バランスは未調整） |

試作したが採用しなかったもの: じんとりペイント（paper.io 風の陣取り）。コードはリポジトリに入れていない。

子どもが実際に好きなのは「モンスターサバイバル」。いちばん期待されているのは `defense`。

### 調べたこと（子どもに受ける要素）

- 低学年に人気のアプリは「タップとドラッグだけで気持ちよく動かせる」もの（マージドラゴン、ぴよ盛り など）
- Hole.io のようなゲームは、のみこむとすぐに成果が見えて、大きくなることで上達を実感し続けられるのが受ける理由とされる
- モンスターサバイバル: 「タタ」をドラッグでレーンに置き、押し寄せるゾンビを自動で迎え撃つタワーディフェンス。モンスターはピンボールで集め、合体・進化で育てる

## 共通のしくみ（`src/lab/common.ts`）

- `LabScene`（抽象クラス）: 各ゲームはこれを継承して `setup()` / `tick(dt)` / `result(cleared)` を書く
  - `cfg: LabConfig`（`avatar` / `easy`（年長） / `seconds` / `onEnd`）
  - `t`（経過秒）、`finish(cleared)`、`timeUpCleared()`（時間切れのときクリアにするかどうか）
  - 演出: `hitstop(ms)`（ヒットストップ）、`popText`（数字などの浮き文字）、`burst`（アイコンを飛び散らせる）、`ring`（広がる輪）、`icon`
  - `enableStick()`: 画面のどこを触ってもそこを中心に動かせるスティック（`this.stick.dx/dy` が -1〜1）
  - 開発サーバーで動かしているときだけ `window.__lab` にシーンを入れる（自動プレイテスト用）
- `HudScene`: タイマー・スコア・ハート・スティック・画面中央の大きな文字（`hud.big()`）。ゲーム側のカメラをズームしても大きさが変わらないように、別のシーンに描いている
- `sfx`: WebAudio で合成した効果音（音の素材はいらない）。`hit(combo)` / `pop(pitch)` / `boom` / `hurt` / `shoot` / `up` / `fanfare` など
- `startLab(parent, Scene, cfg)`: Phaser の Game を作って `hud` と `lab` の2つのシーンを起動する
- 画面: `src/ui/screens/lab.ts`（ゲーム一覧 → プレイ → 結果）。**バトル券は使わず、ごほうびも出ない**
- 画像は今あるもの（`public/sprites/` の主人公・敵・アイコン）を使い回している。新しい画像が要るときは `docs/02-asset-generation.md`

### 「本格実装」でやること（どのゲームにも共通）

雛形は「操作感を試す」ところまで。本格実装では、ふつうは次の4つが必要になる。**どこまでやるかはユーザーに最初に確認する**（下の「最初に確認すること」）。

1. **ゲームの仕上げ**: バランス、演出、はじめて遊ぶときの説明（年長さんは字が読めない前提で、絵と動きで伝える）
2. **学習とつなげる**: 今のバトルは、レベルアップのたびにクイズを出し、正解するとスキルが「スーパー」になる（`src/ui/screens/battle.ts` の `levelUpDialog`）。クイズを出す間は Phaser を止める必要がある（`BattleScene` は `paused` フラグと `async levelUp()` でやっている。`LabScene` にはまだ止めるしくみがない）
3. **お金・強化とつなげる**: バトル券を1枚使う、終わったらコインをもらう（`src/state/economy.ts` の `runReward`）、「つよくする」の強化（`hp` / `atk` / `speed` / `magnet`）をゲームに効かせる
4. **ホームからの入り口**: 今の「バトル」を置きかえるのか、並べて選べるようにするのか

最初に確認すること（ユーザーの判断が要る）:
- 上の 2〜4 をやるか、まず 1 だけにするか
- 今の「バトル」を残すか
- 「つよくする」の4つの強化を、このゲームでは何に効かせるか

## 自動プレイテスト

`scripts/playtest.mjs` は、ヘッドレスブラウザでゲームを動かし、10秒ごとのスクリーンショット（`playtest-out/`、git には入れない）と状態のログを出す。バランスを変えたら、これで「うまい遊び方」と「へたな遊び方」を比べる。

```bash
npm i --no-save playwright && npx playwright install chromium-headless-shell   # 最初に1回
node scripts/playtest.mjs defense auto --seconds=200     # しょうかん + がったいを完ぺきにやる
node scripts/playtest.mjs defense nomerge --seconds=200  # しょうかんだけ
node scripts/playtest.mjs sling auto --seconds=60
node scripts/playtest.mjs grow auto --seconds=60
```

ブラウザで試すときは `npm run dev` → 子どもを選ぶ → ホーム下の「あそびラボ」。

## モンスターまもり（`defense`）

### いまのルール
- 画面は左からピンボール（幅 `PW`=230px）、3×4 のマス（`COLS` × `ROWS`、行がレーン）、柵、敵が来るフィールドの順。横長の画面が前提
- **しょうかん**: コイン（最初 40）を払って玉を落とす。受け皿5つ（`BUCKETS`）: 両はし★は「ラッキー」でランダムな仲間の Lv2、ほかの3つは まほう / ほのお / しゅりけん の Lv1。費用は `min(24, 10 + しょうかん回数)`。マスが空いていないと費用を返す。新しい仲間は柵に近い列から埋まる
- **仲間**（`KINDS`）。見た目は主人公の画像を使い回している
  - まほう（wizard）: 先頭の敵を追いかける弾。0.65秒ごと、ダメージ1
  - ほのお（dino）: 放物線で飛んで範囲ダメージ（半径 60+12×Lv）。1.5秒ごと、ダメージ2
  - しゅりけん（ninja）: 自分の列を横一列につらぬく。1.1秒ごと、ダメージ1.5。**レーンが意味を持つのはこの仲間だけ**
  - レベルでの強さ: `power(lv) = 2.2^(lv-1)`、最大 Lv5
- **がったい**: 同じ種類・同じレベルの仲間をドラッグで重ねる。違う仲間の上に置くと入れかえ、空きマスに置くと移動
- **敵**（`ZOMBIES`）: 右から自分のレーンをまっすぐ進み、柵で止まって1.4秒ごとにたたく（ハートが1減る、ボスは3）。ハートは10（年長さんは15）。出てくる間隔は `max(0.3, 1.2 - t/90)` 秒、体力は `×(1 + t/35)`。出やすさに重み（`weight`）がある。残り30秒でボス（ドラゴン、体力500、年長さんは250）
- 倒すとコインが左上へ飛んできて増える。3分守りきればクリア

### バランス調整の記録（自動プレイ）
| 調整 | 完ぺきに遊んだ場合 | がったいしない場合 |
|---|---|---|
| 最初の版 | 139秒で負け（後半コインが足りず、ゴーレムに押される） | - |
| コイン増・費用減 | 無傷でクリア（簡単すぎ） | 無傷でクリア |
| **いまの値**（体力 t/35、出現間隔を短く） | **無傷でクリア・420体以上倒す** | **113秒で負け** |

→ がったいしないと勝てない。実際の子どもは、この2つの間になるはず。

### わかっている問題・未実装
- マスが全部埋まると、コインの使い道がなくなる（ログでは900枚以上あまった）
- 柵が破られはじめると一気に負ける（ハートが10→0 まで数秒）
- 属性（相性）がない。元のゲームでは重要な要素
- 仲間の見た目が主人公の使い回し。専用のモンスター画像があるとよい
- 縦長の画面には対応していない
- 「同じ仲間を重ねると合体」に子どもが自分で気づけるかは未確認。合体できる組を光らせるなどの手がかりが要るかも
- 学習とつなげる案: 正解するとピンボールの玉が1つ増える／★の受け皿が広がる

## ひっぱりアタック（`sling`）

### いまのルール
- 画面は固定の闘技場（カメラは動かない）。上の64px（`TOP`）はHUD
- **操作**: 画面のどこでも、触って引っぱって離すと、引いた向きと逆に飛ぶ（モンスト式）。引いた長さ（最大 `MAX_PULL`=170px）で速さ 450〜1600。飛んでいる途中でも撃ち直せる
- 摩擦で減速し（1秒で約4割に）、壁で跳ね返る
- **速さが `FAST`（260）より速い間は無敵**で、当たった敵を吹き飛ばす（ダメージ `1 + 速さ/700`）。遅いときに敵に触られるとハートが1減り、はじかれる。ハートは5（年長さんは8）
- **連鎖**: 吹き飛んだ敵（速さ280以上）がほかの敵に当たると、その敵も吹き飛んでダメージ1。1回の発射で当たった数がコンボになり、5以上で「◯コンボ！」
- **ウェーブ**: 全部倒すと次のウェーブ（数 `4 + wave×3`）。5ウェーブごとにボス（跳ね返されて、吹き飛ばせない）。敵は画面のふちから出る（`TYPES`）
- 2分で終わり

### わかっている問題・未実装
- バランスは未調整。自動プレイ（25秒）では、3ウェーブで27体・最大4コンボ・無傷
- 連打すれば常に無敵でいられるので、緊張感が出ないおそれがある（撃つ回数の制限、たまるまで待つ、などの案）
- 年長さんに「引いた向きと逆に飛ぶ」が伝わるかは未確認
- 敵が主人公のすぐそばに出ることがある
- 残像が濃い（`trailCd`）
- 学習とつなげる案: 正解すると次の1発が「スーパー」（つらぬく・大きくなる）

## ぱくぱくビッグ（`grow`）

### いまのルール
- スティックで動く。フィールドに果てはなく、主人公のまわりにいつも90個ほどのものが出る（見えないところで出て、遠くなると消える）
- 自分の大きさ `size`（最初48）の85%（`EAT`）より小さいものに触ると食べる。大きさは面積を足すように増える（`sqrt(size² + 相手² × 0.22)`）
- 大きいものに当たると、はじかれて8%縮み、ジェムを3つ落とす。大きいものはゆっくり追ってきて、小さい生きものは逃げる
- 出てくるものの大きさは、今の自分を中心にばらつく（`pickSize`）。見た目は大きさの近いもの（`KINDS`：ジェム → りんご → … → ドラゴン → トロフィー）
- 大きくなるほどカメラが引く（`110 / size` 倍）。地面の模様も小さくなって、大きくなった感じが出る
- `MILESTONES` の大きさを超えるたびに「おおきく なった！」。2分でおわり、結果は大きさ（`size/40` m）

### わかっている問題・未実装
- **序盤に大きくなれないことがある**: 自動プレイ（ぐるぐる歩くだけ）では40個食べても 48→41 に縮んだ。はじかれて縮む量が、食べて増える量より大きい。縮み方を弱める、はじかれた直後は無敵にする、などで直す
- 食べられるものと危ないものの見分けがつかない（大きさでしか判断できない）。危ないものに色の輪をつける、などが要る
- 目標がない（大きさだけ）。「◯mになったらクリア」やステージ制を考える
- 学習とつなげる案: 正解すると一気に大きくなる／一定時間なんでも食べられる
