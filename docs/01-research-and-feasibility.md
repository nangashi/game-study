# 小学校低学年向け ゲーム×学習アプリ：調査と実現可能性の検証

作成日: 2026-09-26 / ステータス: 調査・検証フェーズ完了、方向性の確認待ち

## 1. 前提（依頼内容から読み取ったもの）

| 項目 | 前提 |
|---|---|
| 対象 | 小学1年〜低学年（1〜3年くらい） |
| デバイス | Android タブレット（ブラウザ / PWA） |
| コスト | 無料で運用（Cloudflare の無料枠） |
| 好み | ダダサバイバー（ローグライト・オートバトル）、Roblox（アバター・拠点づくり・収集） |
| 要件 | 全教科をそろえる / ゲーム内の成長と勉強を連動させて続けられるようにする / 手書き文字認識は「できれば」 |

## 2. 既存アプリの調査：取り込みたい機能

| アプリ | 良い点 | 取り込み方 |
|---|---|---|
| すらら（国内1位の評価が多い） | **無学年式**：つまずいたら下の学年に戻って復習できる | 単元をスキルツリーで管理し、苦手なところは前提単元に自動で戻す |
| RISU算数 | 算数だけに絞ったステージ制と、進み具合の見える化 | 算数は「ステージクリア」形式にする |
| シンクシンク | **1日の問題数に上限**をつけて、日を分けて挑戦させる。「前はできなかったけど、日を空けたらできた」という成長を感じやすい | 1日のゲームプレイ回数に上限をつける（やりすぎ防止と、翌日に戻ってくる動機づけ） |
| Prodigy Math | RPG の中で問題に答えると戦える。**ペット育成とレベルアップ**への愛着がやる気になる。難易度を自動で調整 | 戦闘・強化の燃料を学習にする。難易度はアダプティブ |
| Blooket | 正解すると **3つの宝箱** から選べる（Gold Quest）。タワーディフェンスなど**同じ問題を別のゲームモードで遊べる** | レベルアップ時のスキル選択とクイズを組み合わせる。問題セットとゲームモードを分けた作りにする |
| Duolingo / Duolingo ABC | 連続日数（ストリーク）、**間隔反復**、1回を短く終える設計 | 忘れかけた問題を出し直す（間隔反復）。ストリークには「おやすみチケット」をつけて罪悪感で引っぱらない |

注意点：Prodigy には「ご褒美がゲームの楽しさに寄りすぎて、学習効果に結びつかない」という批判があります（Fairplay for Kids など）。**課金・射幸性のあるガチャ・広告はなし**にして、ご褒美は「正解数」より「取り組んだこと」（再挑戦・毎日つづけたこと）に結びつけます。

## 3. コンセプト案：「まなびサバイバー」（仮）

```
[まなびクエスト 5〜10分]  問題を解く → コイン・経験値・素材
        │  （1日の上限あり／保護者が変更できる）
        ▼
[サバイバーラン 3分]      ダダサバ風オートバトル。移動だけで操作できる
        │  レベルアップ時の3択スキル選択 ＝ クイズ（正解すると★が1つ上のスキル）
        ▼
[きち（拠点）]             Roblox風：アバター着せ替え、拠点の建築、ペット、図鑑あつめ
        │  強化・解放にはクエストで得た素材が必要
        └──→ 次の日のクエストへ（間隔反復で復習問題が混ざる）
```

- **成長と学習の連動**：武器・ペット・建物はそれぞれ教科とつながっている（例：算数で「ひかりの石」、国語で「ことばの羽」）。いろいろな教科をやると強くなる
- **教科ごとのボス**：単元の確認テストをボス戦にする（例：ひらがなボス、九九ドラゴン）
- **手書きを使ったゲーム**：書いた字が魔法になる（「ひ」→ 火の魔法）。書き取りの練習がそのままゲームのアクションになる

### 教科の構成（低学年の学習指導要領にそろえる）

| 教科 | 内容 | 問題の作り方 |
|---|---|---|
| 国語 | ひらがな・カタカナ（書き・読み）、漢字（1年80字・2年160字・3年200字）、ことば、文の読み取り | 手書き判定＋選択式。漢字リストは学習指導要領の配当表から |
| 算数 | たし算ひき算、くりあがり、時計、長さ・かさ、九九（2年）、図形 | **プログラムで自動生成**（作成コストほぼゼロ） |
| 生活／理科の入口 | 生き物、季節、植物、からだ | 手作り＋LLMで下書き → 保護者がチェック |
| 英語 | 単語・あいさつ（音声中心） | 音声＋絵の選択式 |
| 思考力 | パズル、プログラミング的思考 | ルールから自動生成 |

※ 社会・理科は3年生から。低学年は「生活科」の範囲にします。

## 4. 技術構成案

| 層 | 選択 | 理由 |
|---|---|---|
| ゲーム | **Phaser 4**（2026年4月に正式版） + TypeScript + Vite | 2D に強い。モバイル向けの最適化が多く、スプライトを数百体出すサバイバー系でも向いている |
| UI | Phaser の上に DOM（または Preact） | 問題画面・保護者画面は DOM のほうが作りやすい |
| 配布 | **PWA**（ホーム画面に追加 → 全画面・オフラインで動く）。必要なら TWA で APK にもできる | ストア申請なしでタブレットに入れられる |
| ホスティング | **Cloudflare Workers の静的アセット**（または Pages） | 静的配信は無料・無制限。ビルドは月500回まで |
| セーブ | 端末の IndexedDB が正。必要なときだけ Worker + **D1** に同期 | オフラインでも遊べる。D1 無料枠は 1日あたり 読み500万行・書き10万行、容量5GB。**2026-09-01 から超過するとエラーになる**が、家族で使う規模なら十分 |
| 保護者画面 | Worker + D1、Cloudflare Access（無料枠）で保護 | 子どもの個人情報は持たない（ニックネームだけ） |
| 音声 | Web Speech API（ja-JP）。端末によって声がない・ネット接続が必要な場合は、事前に作った音声ファイルを使う | 1年生は読めない字があるので、問題文の読み上げは必須 |
| 手書き | 自作の1画判定（下記）＋ KanjiVG の筆順データ | 端末の中だけで動く。サーバー不要 |

Workers の無料枠（1日10万リクエスト、CPU 10ms/回）を使うのは同期と保護者画面だけです。ゲーム本体は静的配信なので、家族で使う分には上限に届きません。

## 5. 実現可能性の検証：手書き文字認識

### 5.1 2つの方式を比べた

1. **汎用認識**（何を書いたか当てる）：[Kanji Canvas](https://github.com/asdfjkl/kanjicanvas)（MIT、ブラウザだけで動く、常用漢字2213字）。かなは同じリポジトリにある手書きサンプル144字から参照パターンを作成
2. **お手本との照合**（書くべき字が分かっている前提で、1画ずつ判定）：[KanjiVG](https://kanjivg.tagaini.net/) の筆順データ（CC BY-SA 3.0）と照合する自作ロジック → `prototypes/handwriting/judge.js`

学習アプリでは「この字を書いてね」と出題するので、書くべき字はほぼ必ず分かっています。そのため方式2が本命です。

### 5.2 検証方法

KanjiVG の筆順から、子どもっぽい崩れ（全体の傾き・せん断・縦横比、1画ごとの位置ずれと長さのずれ、線のゆれ、マスの中での位置・大きさのずれ）を乱数で加えた疑似手書きを作り、1文字につき5パターンで評価しました。「歪み1.0」はかなり崩れた字です。

### 5.3 結果

**方式1：汎用認識（Kanji Canvas）**

| 対象 | 候補にする文字 | 1位正解 | 上位3位に入る |
|---|---|---|---|
| ひらがな | ひらがなのみ | 78% | 93% |
| ひらがな | 全文字（漢字＋かな） | 55〜60% | 76〜84% |
| カタカナ | カタカナのみ | 63〜67% | 91〜93% |
| 1年漢字 | 常用2213字 | 59〜62% | 81〜86% |
| 2年漢字 | 1〜2年の240字 | 90% | 97% |

→ 「何を書いたか当てる」用途としては弱い（「ロ」と「口」、「へ」と「ヘ」など形が同じ字もある）。書くべき字が決まっていない自由入力のときに、候補をしぼって使う程度にとどめます。書き順がバラバラでも精度はほぼ変わりません（ひらがな 1位75%・上位3位92%）。ただし遅く、18画の字を常用2213字と照らし合わせると PC でも1回あたり約0.5秒かかりました。タブレットではさらに遅くなるので、候補をしぼる必要があります。

**方式2：お手本との照合（自作、1画ずつその場で判定）**

| 対象 | 条件 | 正しく書いた字が合格 | 別の字を書いたのに合格 | 書き順の入れ替えを検出 | 逆向きの画を検出 |
|---|---|---|---|---|---|
| ひらがな | 歪み0.5・ふつう | 100% | 3.5% | 100% | 100% |
| 1年漢字 | 歪み0.5・ふつう | 100% | 0.3% | 100% | 100% |
| 2年漢字 | 歪み0.5・ふつう | 99.9% | 0% | 98% | 100% |
| ひらがな | 歪み1.0・やさしい | 97% | 9.6% | 100% | 100% |
| 1年漢字 | 歪み1.0・やさしい | 95% | 0.8% | 97% | 100% |
| 2年漢字 | 歪み1.0・やさしい | 91% | 0.5% | 92% | 100% |

→ **実用になる見込みが高い**。1画ごとの判定は0.1ms程度。しかも「書き順がちがう」「向きが逆」「形がおしい」を区別して子どもに返せるので、学習上の価値も高いです。

### 5.4 ブラウザでの動作確認

`prototypes/handwriting/index.html` をヘッドレス Chromium（タブレット相当の 800×1280）で操作して確認しました。

- 「あ」を正しく書く → 「できた！」
- 2画目から書く → 「かきじゅんを たしかめよう」＋書くべき画を光らせてヒント
- 1画目を逆向きに書く → 「むきが ぎゃく かも？」
- 18画の「曜」を正しく書く → 「できた！」
- コンソールエラーなし

### 5.5 残っているリスクと限界

- **疑似データでの評価なので、実際の子どもの字では精度が下がる可能性があります**（お手本と評価データが同じ KanjiVG 由来のため、楽観的な数字です）。→ タブレット実機で、お子さんに書いてもらって確認するのが次の一手です。許容度（やさしい／ふつう／きびしい）は画面で切り替えられます
- とめ・はね・はらいは判定していません（線の形と向きだけ）
- 画をつなげて書く（続け書き）と画数が合わず不合格になります。低学年の書き取りなら、むしろ望ましい挙動です
- ペンを使っているときは指のタッチを無視する、簡易的な手のひら対策を入れてあります
- KanjiVG は **CC BY-SA 3.0**。アプリ内にクレジットを表示し、そこから作ったデータ（`strokes-data.js`）は同じライセンスで扱う必要があります。1〜6年の漢字1026字を入れても、データは約700KB（gzip で数百KB）

## 6. そのほかの実現性評価

| 項目 | 判定 | コメント |
|---|---|---|
| Cloudflare 無料枠で運用 | ◎ | 静的配信は無制限。D1 の上限も家族で使う規模なら問題なし |
| タブレットでのゲーム性能 | ○ | Phaser 4 はモバイルの WebGL を大きく改善。中位機種なら敵200〜300体でも現実的。実機での計測が必要 |
| オフライン動作 | ◎ | PWA＋IndexedDB |
| 日本語の読み上げ | △ | Android Chrome は端末によって声がない・ネット接続が必要なことがある。実機で要確認。だめなら音声ファイルを事前に作る |
| 教材を全教科そろえる | △（工数が最大のリスク） | 算数は自動生成できる。国語はデータがそろう。生活・英語は手作りが必要 → LLMで下書きして人がレビューする運用 |
| 継続性（飽きさせない） | ○ | 間隔反復＋1日の上限＋コレクション要素。開発中はお子さんの反応を見ながら調整したい |

## 7. 進め方の案

- **フェーズ0（完了）**：調査、手書き判定の検証
- **フェーズ1（MVP・2〜3週間ぶん）**：ひらがなの書き取り＋たし算ひき算 → コイン → サバイバーラン1ステージ → 強化1系統。ローカル保存。PWA で Cloudflare に配信
- **フェーズ2**：カタカナ・1〜2年漢字、時計・九九、拠点づくり・ペット・図鑑、間隔反復、保護者画面＋D1同期
- **フェーズ3**：生活・英語、教科ボス、季節イベント

## 8. 確認したいこと

1. **お子さんの学年と人数**（兄弟で使うならプロフィールを分ける）
2. **タブレットの機種**（性能の目安、スタイラスペンがあるか）
3. **公開範囲**：家族だけ（認証で保護）か、一般公開も考えているか。一般公開なら、個人情報・ライセンス・保護者同意の扱いが重くなります
4. **ゲーム時間のルール**：「勉強した分だけ遊べる」式でよいか。1日の上限は何分くらいか
5. **教科の優先順位**：まず国語（書き取り）＋算数でよいか。英語は入れるか
6. **開発体制**：ほぼ私（Claude）が実装し、ご自身はレビューと実機テストを担当する形でよいか。TypeScript＋Phaser でよいか
7. **ご褒美の方針**：ランダムの宝箱（ガチャ風）を入れてよいか。射幸性を避けて、確定報酬だけにするか

### 回答（2026-09-26）

- 子どもは **年長と小2の2人**。タブレットは**ペンなし**（指で書く）。**家族だけ**で使う
- 日本語の読み上げは**なし**でよい → 年長さん向けは、字を読まなくても解ける問題（絵をかぞえる、なぞり書き、同じ字さがし）にする
- 仕様は上の案で進め、触りながら調整する → フェーズ1（MVP）を実装（README 参照）
